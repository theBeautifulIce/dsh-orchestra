# ADR 0001：编排账本用单库单写者，存储驱动走 node:sqlite

- 状态：已接受（2026-11-13）
- 影响范围：规格 §2、§4；实施总纲 §4.1.1；S1 计划

## 背景

编排要跨会话、跨插件、可恢复地续跑，因此需要一个所有会话都能读、只有一处能写的事实源。宿主侧多插件并存，若每插件各持一份状态，重启、升级、回滚都会出现两份都自称最新的局面。

## 决定

1. 账本是一份 SQLite 单库，写入只有一个执行者：独立进程 orchestra-service。
2. 存储驱动只用 Node 内置 node:sqlite 的 DatabaseSync，不引第三方 SQLite 包；仓库里唯一允许 import 它的是 src/infra/sqlite/driver.ts。
3. 所有写事务走 BEGIN IMMEDIATE，并在事务内校验 service_meta.instance_epoch 等于当前实例代号；跨代写入一律拒绝。
4. 行级 CAS 与 revision 是线性化点；所有迁移带 CAS，CAS 失败不产生副作用。
5. 账本只追加：已提交事件不改写，事件序号单调（不变量 I2）；一个 node_run 与一个 run 最多一个终态（不变量 I1）。

## 理由

- 单写者把谁改了状态这个问题消掉了：状态变更只发生在服务侧，面板与工具都是投影与命令。
- 内置模块免编译、免安装、免版本漂移；engines 已把 Node 下限抬到 ^22.19.0 || >=24.0.0，该版本起 node:sqlite 不再需要 --experimental-sqlite。
- epoch 校验让服务重启后旧实例还在写这类故障有了确定的拒绝点，而不是靠时间窗猜。

## 后果

- 服务不可用时写入路径明确失败（面板只读仍可用），不静默降级。
- 多机部署被这一条挡住；真需要时再开 ADR 002 讨论。
- 迁移编号必须分段，否则六批并行会撞号。
- node:sqlite 仍是实验特性（Node 26 免旗标可用），宿主换版本时要重跑 S1 的冒烟。
