# F8 普通执行裁决补证

生产装配在 S6 从维护扫描生成启动不明、动作超时和待核实卡。新卡以签名节点事件绑定节点、尝试、动作代次和续期代次。普通放弃建立运行级签字卡，同一运行的后续放弃追加成员并增加签字卡修订。签字和停止事实分开记录。运行收口要求每个放弃节点均有当前代次的有效签字及宿主停止记录。记忆对账仍使用自己的受控命令。

| 出口 | 实测结果及边界 |
| --- | --- |
| M-10、M-53 放弃 | S6 扫描从 `startup_unknown` 和 `indeterminate_side_effect` 开卡，真实 HTTP 从两种状态执行放弃。重复提交返回同一回执，旧签字卡修订拒绝，客户端虚填停止时刻拒绝。受生产条件约束的 M-36 分支通过同一命令接线，本轮真实 HTTP 对 `action_overrun` 验证的是 M-33。 |
| 普通放弃后的签字 | 真实 HTTP 批准聚合签字，进程重启后重放同一回执。另一个合同用扫描时钟到达签字截止时触发 `expired_final`，原运行暂停，未核实记录保留，过期回执不能放行。批准的正例在所有当前节点停止事实齐全后进入 `succeeded_with_unverified`。 |
| M-33、M-51 | 真实 HTTP 指定系统证据并确认业务效果，分别从 `stopping` 和 `indeterminate_side_effect` 进入 `done`。同事务写效果结算和签名裁决事件。缺失与外部证据、旧动作代次的停止记录、请求自报停止时间均拒绝。 |
| M-52 | 真实 HTTP 确认业务效果未发生后走 `failed`。原尝试不变，不建下一尝试。缺少工作流独立幂等授权及迟到回报冻结前，不开放 `superseded` 重试。 |
| M-59、M-60 与 I4 | 重跑原合同。报告冲突仍走已登记回报和原裁决入口。终态证据表的原用例继续验证业务效果、执行证据与终态事件。 |
| M-34、M-37 | 仍待实现。同一执行器需要能继续被订阅并受允许预算约束。当前生命周期超时会取消监听，单改数据库截止时间不能恢复实际跟踪。 |
| M-07 | 本机 HTTP、SQLite 和生产 DSH 桥验证迟到建会话收据。宿主核对同一节点、尝试、动作代次和子会话，确认它空闲、从未接收指令、没有请求头或工具事件，先封住发送入口再释放子会话。服务回查当前续期代次、运行取消状态、账本和报告记录后写签名收据。裁决关闭本卡并释放租约，步骤进入 `failed`，原尝试和代次不变。收据提交后重启仍可审批，重启时无收据、桥未实现专用能力、运行已取消、旧修订及迟到报告均被拒。 |
| M-06、M-08、M-09、M-57、M-61 | M-06 仍需要固定版本的明确幂等授权，当前普通执行工作流无该字段。超时的创建请求在返回前没有可重接的执行器，返回后走上面的封存路径。已启动节点因租约失效转入启动不明时，旧租约被撤销。确认启动和继续跟踪仍需实际重接有权运行的当前尝试。S6 独立确认启动路由现拒绝无重接证据的人证。 |

生产停止写入点在 Agent 生命周期确认宿主空闲、检查执行器状态及释放成功之后，重新读当前节点、执行器身份、尝试和动作代次。工具出箱还有未完成项时不写停止记录。效果出口还要求受信核验器的 `tool_finished` 证明与固定工作流定义哈希、当前尝试和动作代次一致。HTTP 合同在真实本机 S6 路由上运行。输入采用合成账本和宿主收据夹具，业务证明由生产证据收集器计算，未用现网执行器。签字后的重启验证使用同一 SQLite 文件。

启动裁决仅在单调钟仍待到期且有正的剩余预算时创建。看门狗到期、桥挂起和已登记报告收口时撤下原卡。常规步骤的生产启动一并登记执行器和会话身份，生命周期释放后可写入同一尝试的宿主停止收据。合同使用合成 DSH 子会话和工具结果，经过生产桥、执行生命周期、HTTP 认证及 SQLite 写入，未连接外部模型。
