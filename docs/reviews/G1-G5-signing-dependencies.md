## 授权人操作

1. 从含上述冻结提交和五份独审报告的干净完整仓库开始，核对报告里的 `candidate_commit` 和表中轮次。若冻结之后改过候选文件，先为新候选取得对应审计报告。
2. 准备 G1–G4 的现存记录。首次准备 G5 时运行 `node --no-warnings scripts/gen-g5-record.ts tmp/G5-draft.md`，核对生成的 73 项、73 份证据和 6 条不变量，再将草稿放到 `docs/gates/G5.md`。整理草稿时，更新人读的候选范围及当轮审计说明，去掉模板提示，对照报告逐项核准。历史轮次说明须标明其所属轮次。
3. 在收到相应门的真实批准后，把批准人和实际批准时间同时写入可见正文与 GateArtifact 的 `approver`、`approved_at` 字段，把 `audit_round`、`audit_report` 指向上表正确报告。模板中的示例人名和时间、旧记录的批准信息均须替换。先提交准备好的记录，使签署入口读到干净工作树。
4. 从 G1 开始。运行 `node --no-warnings scripts/sign-gate.ts docs/gates/G1.md`，将该文件单独加入 Git 并提交，再运行 `node --no-warnings scripts/gate-check.ts docs/gates/G1.md`。依次对 G2、G3、G4、G5 做相同操作。每次都先确认上一门签署已提交并通过单门检查，因为下一门从 HEAD 取前序摘要。签署脚本会重算哈希。
5. 最后一门提交后，在同一干净 HEAD 上依次执行以下两条命令。两次均须退出 0，各输出 G1 至 G5 五条通过记录，才可登记正式过门。

```sh
pnpm gate
node --no-warnings scripts/gate-check.ts docs/gates/G1.md docs/gates/G2.md docs/gates/G3.md docs/gates/G4.md docs/gates/G5.md
```
