### 分批派工

1. **首批**：T01 先冻结报告、适配与失败契约。T07 可并行盘点生产查询与数据集；T14 可并行盘点真实上一版构建、存量库和可逆路由。X01 先独立观察目标 DSH 启用链。每位执行者只领一个有明确落点的子单。
2. **场景与观测**：T01 的公共接口经主代理审核后派 T02–T06 的独立场景，T07/T08 产出可复跑的测量与背压探针。T04 与 T08 共用 G-08 的对账证据；T06 先交 G-14/15/16，G-13 的最终验收消费 T14 的真实双构建驱动。T14 的**驱动开发**先于该最终验收，不能等待 G-13 已绿才开始。T10/T11 可在各自边界推进，X02 从既有功能回归入手。
3. **工具就绪**：T09 可先验证采样器的短窗口和故障恢复；正式 24 小时从稳定候选开始。T12/T13 可先开发流程、确定性政策、终态外收口器和双份校验的正反例。T15/T16 先备好手册、模拟演练、试圈准入及回退检查。T17 先验证可重复打包和隔离安装。上述任务的开发态样本只能作为测试夹具。
4. **候选与门前实跑**：把代码、测试、配置、安装说明和门校验器合并后指定完整候选 SHA。用该候选跑故障、真实性能、全程滞后与 24 小时浸泡、负载升级回滚、手册演练和安装冒烟。依 §14.6 先执行 R0；依 §11.6 留连续 3 天无 P1、历史门对应项和回滚演练记录。该观察是推进顺序的一环，G6 机器必过清单单独按 §11.2 判定。T12/T13 用完整证据和真实人批走正式路径；T17 作独审及联检交接。受影响的候选输入变化时登记新 SHA、失效的证据和重跑范围；跨越最后一次候选变化的测量不得拼接成合格窗口。
5. **放行后运营**：T16 拆开准入规则验证与实际观察。门前 R0 的实绩作为 R1 准入输入。实际升圈须满足该圈条件并取得对应授权，R1/R2 的真实观察记录随进展补记。T17 无需等未来 R2 完成才验证 G6；真实部署也不能以“开发卡已完成”代替部署判定。

## 给所有执行者的共同约定

- 主代理下发本页、具体任务卡、依赖回执和准确工作树。卡内“拟新增”的文件或命令是交付目标，先查实际代码及调用者。若已有入口能满足需求，直接复用并交出通过与拒绝的证据。开发期可用 `pnpm exec vitest run <卡内测试文件>`；`pnpm check` 为完整类型、测试与构建。零命中、条件跳过、fixture 成功、全量通过数区分记录。
- 一位执行者一次负责一个写入域。T01 负责公共报告、分发及旧证据适配；T02–T06 对共享 `scripts/fault-inject.ts` 的修改由主代理串行整合。T08 统筹公共 HTTP/队列观测接线；T10/T11 向所有者交最小差异。T12 管工作流与 policy，T13 管原像与双份校验，T17 管包、README 与门 CLI 集成。T16 管圈状态与入流守卫，T10 验证该守卫的真实授权边界，T12/T14/T15 只消费已公布接口。T06a 持有备份实现和专测，T14 持有升级驱动。共享配置、迁移清单、同一测试文件或门注册表均排队；跨卡契约由主代理先公布版本和示例，任何一方不得自行改两端取绿。
- 明天在隔离工作区、独立账本/profile/输出目录运行。只在获准的工作区和工具范围内测试。用 `--out` 保留旧 G1–G5 证据字节；外部模型、真实 DSH、Go 插件、回环模型和测试替身分别标注。缺真实依赖时交付可完成部分，余项写明所需版本、权限、负责人和重跑命令。签署批准、实际发布、通知值班人、外部写入及升圈分别按其授权办理。
- 每卡交回：基线和候选完整 SHA、修改文件和理由、测试名及实际命中数、含参数的命令和退出码、数据/环境、正向与负向结果、原始证据位置和哈希、跳过与遗留。集成者在同一候选复核接口、回执、证据文件及其哈希；只读独审与实现分人。分批收口、推主线前、签门前及高风险迁移/时钟改动按仓库审计规范原文派审，附 §4/5/6、不变量、上轮报告及未结问题。阶段退出以真实必过项、独审、授权及同树门检查为准。[审计要求](../../../审计要求.md)
