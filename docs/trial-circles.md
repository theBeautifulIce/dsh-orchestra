# S6 试用登记

截至 2026-11-20，本次开发演练使用临时账本。真实工作区、值班人到达记录和观察起点须由现场宿主登记。

| 圈 | 使用范围 | 离开本圈前要核对的事实 |
| --- | --- | --- |
| R0 | 固定候选的隔离沙箱、合成工作负载与测试执行器。 | 连续 3 天，负载及水位记录完整，无 P1，既有门复核和带负载回滚通过。升 R1 还要已签 G6 及本次开放批准。 |
| R1 | 一个受信仓库工作区。批准的只读工具与固定版本流程。记忆可以提交提议。 | 连续 7 天无 P1，面板停点和账本能对应，值班覆盖有效。另行批准进入 R2。 |
| R2 | 保留 R1 仓库，加入经批准的沙箱、只读检查流程及工具清单。 | 连续 14 天无 P1，每日有复盘，事故能在 30 分钟内定位，复验值班手册后提交 S6 最终审查。 |

## 宿主如何登记

1. 在受控宿主启动参数 `trial` 中提供冻结的候选提交、实际工作区 ID、类型与物理根目录。宿主对合成执行器、工作区注册和工具本身的只读语义负责。安装包保留默认阶段。已有试用账本在重启后继续检查原批准。
2. 读取 `orchestra.trial.get()` 获得当前圈、修订和本圈起点。宿主授权器 `authorize` 须逐项核实候选、来源圈、目标圈、修订、工作区、流程定义哈希、只读工具清单、已签 G6 及连续观测的实际内容。请求正文里的姓名或自填经过时长不能作为授权。
3. 授权人批准后运行 `advance(proof, target, scope, revision)`。服务在同一写事务内追加登记、校验时间窗及批准有效期。切换到获准工作区后，从正常开任务入口发起只读检查，抽查固定流程、实际工具、面板停点和审批记录。处在仓库或沙箱工作区时，即使审批记忆写入，服务也会在外部调用前拒绝。
4. 发现不变量或权限边界事故，通过 `stop(proof, reason)` 退回 R0 并暂停新入流和受影响的执行。保留下已有账本供排查。获得恢复批准后，在合成宿主用当前修订调用 `restartSynthetic`，重新开始观察。值班超时产生的独立暂停还须按值班手册确认。

每次观察保存候选和包摘要、工作区别名、实际起止 UTC、业务负载、事件水位、告警和人工交接原件。R2 最终审查另外核对两周事实。对外发布或真实工作区启用以实际获批范围为准。[值班与回滚手册](runbook.md)
