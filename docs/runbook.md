# S6 值班与回滚手册

值班人登记为 `human:啸春`。演练开始时记录实际当班人、阶段负责人、代班、UTC 时间、当前圈、工作区、安装包摘要、账本位置和可用通知渠道。观察期与演练回执分别归档。正式 QQ 通知需要当班人确认渠道和发送权限。

## 接到告警

1. 定位 run 与节点尝试。保留实际告警、节点事件、租约、工具及审批回执、水位、候选 SHA 和包摘要。复核 I1–I9 或权限边界异常、同类 P1 在 24 小时内两次或跨工作区发生、迁移后状态无法解释，或事件滞后连续十分钟超限且扩容无效。事件窗口单次越限也影响 G6 的独立判定。
2. 当班人可先暂停新运行、隔离问题路由。当前 S6 包导出 `createIntakeControl(db, options)`。宿主将 `authenticate(proof, action)` 绑定其认证系统，返回该动作实际获准的操作人。读取 `get()` 的修订，调用 `pause(proof, reason, revision)` 后记录返回值。在途运行继续收口。旧构建另需在宿主入口停收流量。
3. 面板 inbox 出现告警后，依本页的 QQ 流程通知当班人。登记发出时间、消息编号和人工确认时间。30 分钟未确认时暂停新运行。恢复时先 `ack(proof, pageId, reason)`，再取当前修订，复核水位与风险后调用 `resume(proof, reason, revision)`。
4. 从收到升级起计时，阶段负责人须在 10 分钟内决定回退或前滚，登记理由和恢复条件。确认通道不可用时，保持新入流暂停，保留在途与账本。

## QQ 通知与确认

本机 QQ 接入项目位于 `D:\aboutAI\dshQQ`。已核对 DSH 的 desktop profile 安装了 `dsh-onebot-qq@0.10.0`，Cordis 插件 ID 为 `dsh-onebot`，配置使用 NapCat 反向连接。DSH 插件目录、任务的工作区和 QQ 接收会话各有自己的标识。2026-11-20 核对时，当前用户默认数据目录下的 `media/onebot/chat-sessions.json` 为 `{}`。现场宿主若另设 `DSH_HOME`，按实际运行目录核对。

1. 当班人在日常联系机器人的 QQ 私聊或指定群中可用 `/id` 核对会话，用 `/status` 看当前工作区。群内适用插件现有的管理员和触发规则。交接只需记录值班私聊或群的受控别名、当班人、代班与时间段。路由管理员在宿主绑定具体接收会话。
2. 获准演练的宿主用插件现有的 `qq_send_text` 发出“演练”标记、面板告警编号和需要人工确认的动作。在已绑定的 QQ 会话可以沿用当前目标。从面板发起需明确使用宿主登记的值班目标。插件返回 `sent` 和 `messageId`。仅登记可核对的真实发送，分段发送时插件返回最后一段的编号。
3. 宿主提供 `lookupQqDelivery(inboxId, invocationId)`，核实同一工作区、目标会话、告警与宿主工具调用，然后通过 `recordQqDelivery(proof, inboxId, invocationId, reason)` 登记。登记器拒绝无消息编号及模拟编号；30 分钟从插件实际发出时间开始。该接口供受信宿主装配，登记动作本身不会发送 QQ 消息。
4. 发出后等待当班人确认。值班人在已认证面板确认该告警，或由宿主核对原会话中指定当班人的明确回复后登记 `ack`。插件发送回执只能证明出站有记录。回执缺失或发送结果未知时先核对宿主调用记录，避免重复发给接收人。

## 按阶段处置

| 受影响阶段 | 动作 | 恢复前核对 |
| --- | --- | --- |
| S1 | 停止服务写者，封存账本副本和水位。 | 原始账本完整，单写者锁正常，事件序列连续。 |
| S2 | 隔离问题桥，记录在途 agent 和确认状态。 | 核实桥已停止或恢复，面板可识别阻塞，旧执行者不能继续写新尝试。 |
| S3 | 停新 run，等在途进入安全点，优先前滚。 | 仅在旧引擎已实测能读新账本时回退。 |
| S4 | 撤下问题工作流版本，保留已固定该版本的 run。 | 核固定定义哈希、后继版本及在途来源。 |
| S5 | 关闭受影响面板或记忆写路由，保留引擎与账本。 | 对账已批准和已写条目、确认未核实的副作用。 |
| S6 | 经阶段负责人授权，在双向兼容窗口切回上一过门构建。 | 核两包、事件水位、去重、固定版本、在途与测量窗口。 |

## 升级与有负载回滚

依序保留七步回执，每步记录 UTC、操作者、包摘要、步骤前后水位及失败处置。

1. 对正在使用的账本制作独立备份，核清单与数据库摘要。
2. 在副本验证迁移与双向只读回放，重新核对完整性和存量任务。
3. 在宿主和 S6 新运行入口暂停接单，等到已定义的安全点，登记在途运行和去重键。
4. 启动新构建，检查健康页、阶段、只读查询、事件序号和已固定版本。
5. 在受控工作区跑一条单节点合成任务，核实际执行、结果、证据和终态。
6. 恢复授权的新入流，在约定负载下观察满十分钟，登记提交与订阅水位。
7. 按上表决定回滚或前滚。在同一实时账本上核恢复服务、未重复派发、历史运行可读及期间提交的事件均可回放。备份只恢复到独立路径供核对。

交班时说明哪些能力已开放、仍暂停哪些路由、剩余审批和下次观察时间。测试身份、回环回执、短窗口的结果均需写明来源。
