# S1 第二十轮审计整改对照表

- 审计报告：`docs/audits/S1-independent-audit-round20.md`（审计对象 HEAD `638605c`）
- 整改提交：`24ffd47`「Reject hidden audit negatives and bind evidence hashes」
- 本表用途：逐条对应 P0/P1、改法与回归用例。**本表不作为放行依据**——G1 是否过关由下一轮独立审计决定。

## P0-1 五行拆词仍可签过

- 根因：判定器只在相邻 2..4 行内拼接，五行 `本/报/告不/通/过` 超出滑动窗口。
- 改法：`scripts/gate-check.ts:637-751` 不再按行拼窗口，改为全文 `visible.join('|')` 一次折叠扫描；主语、连接词与结论词之间允许任意 `|`，任意行数的拆词都会连回同一条结论。
- 用例：`tests/gate-check.spec.ts:700`「S1 第二十轮 P0/P1」覆盖五行拆词、行内拆词与斜杠变体。

## P0-2 图片 alt 的零宽字符/组合符/`<wbr>` 可绕过

- 根因：图片 alt 只做 `unescapeAll` 后直接送旧判定器，没走不可见字符归一化。
- 改法：`scripts/gate-check.ts:607-613` 先 `strip tags`，再 `unescapeAll`，再 `normalizeAuditLine`，再进同一折叠扫描器；U+200B、`&ZeroWidthSpace;`、组合符与 `<wbr>` 都会被剥掉。
- 用例：同节覆盖 `![…](x.png)` 的零宽、实体、组合符与 `<wbr>` 四类载荷，期望 null。

## P0-3 德式引号、`〝〞`、`｢｣` 与 emoji 收尾可签过

- 根因：结论词后的尾部 lookahead 只认有限 ASCII/中文标点。
- 改法：折叠扫描命中结论词后，尾部只要求「结束 / `|` / 需应已了的」，不再枚举收尾标点；所有引号、emoji 与不可见符号都已折叠成 `|`。
- 用例：同节覆盖德式 `„…“`、`〝…〞`、`｢…｣`、emoji 尾与多种全角标点。

## P0-4 门正文长行与 24 字偏移窗口可绕过

- 根因：`bodyConclusionOf` 给每行设了 `maxStart:24` 与 `maxLength:160`，超长或后置否定句被直接放弃。
- 改法：`scripts/gate-check.ts:797` 删除窗口，先对全文做一次折叠扫描，再对以「结论/判定」开头的行做完整扫描；保留历史叙述不误杀：裸「结论」不作为正文默认主语，`门记录拿结论为 fail` 仍返回 null。
- 用例：`tests/gate-check.spec.ts:869`「门记录正文的长行与偏移否定句也要拒绝」覆盖 160 字长行、25 字前偏移、五行拆词、德式引号、emoji 与 alt 零宽，注入 `## 必过项与证据` 前，期望抛 /正文结论/。

## P1-1 主语/谓语邻近同义写法仍 pass

- 根因：原词表只有「不通过/未通过/不合格」，不含「没有通过、并未通过、未获通过、未予通过、不能通过、不是通过、通不过、失败、未成功、未过关、不批准」及繁體写法。
- 改法：`FAIL_SUBJECTS` / `FAIL_VERDICTS` / `FAIL_CONNECTORS` 统一扩表（`scripts/gate-check.ts:637-685`）；主语含「审计报告/本次审计/审计意见/最终结论」及繁體，结论词含简繁与英文变体。
- 用例：同 P0/P1 节逐条覆盖；安全句 `本报告不通过项已全部修复`、`本次审计不通过原因如下`、`本报告未通过验收`、`本报告不合格品率为 0`、`本次审计不通过项为 0` 仍 pass。

## P1-2 回归测试只覆盖精确载荷

- 根因：此前每条审计只补具名串，没补同族变体。
- 改法：`tests/gate-check.spec.ts` 由逐串断言改为同族载荷组：S1 r20 的 18 个与 S2 r24 的 36 个都走同一判定入口；另加 `结论ːfail`（U+02D0）与 `The review did not pass.` 两个曾失败用例。
- 用例：三组新用例合计 57 个 payload；运行结果 63 passed / 11 failed，11 红全为预签态。
