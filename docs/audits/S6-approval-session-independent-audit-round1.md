## 2. 原问题与修复核对

| 问题 | 本轮核对结果 |
| --- | --- |
| 待审批事项只在面板出现 | 通知改用 `agent.steer` 到最近一步；待处理事项拥有独立可见节点，不依赖 `turn/end`。持久 ID、丢弃重试与消费后确认保留。 |
| 会话不能直达审批 | 服务端生成绑定来源的 `attentionLinks`；点击重新核对会话、工作区、任务、运行和审批，再打开精确事项。特殊 `review` 返回 `panel_review` 与入口，不猜测结论、不提交批准。 |
| 已执行却再次要求证明启动 | 原日志显示子会话成功调用工具后才失去工具权限。新路径根据同尝试的宿主观察区分已执行的 `stopping` 与确实缺少观察的 `startup_unknown`。 |
| 超时后没有清楚的失败结尾 | 工具拒绝明确停止重试；受严格绑定的纯执行未完成回报可落 `failed` 并关闭超时待办。会话显示本次已采纳报告的原因、下一步与未完成项。 |
| 审批内容难以理解 | 统一说明任务、步骤、处理原因、核对方法、期限和每项操作后果。旧卡缺少事实时保留未知，不借用后续尝试；人工确认仍须勾选。 |
| 看板和关联控件风格不统一 | 待审批入口使用既有 `ops-button`；返工、材料、日志、规划及触发器补齐既有控件样式。原点击定位、事件处理和禁用条件保留。 |
| 终态消息仍可能等主脑结束才显示 | 服务端终态标记使最终结果与原成果链接由独立节点显示；尾部不重复呈现同一终态通知。历史无标记通知保持兼容。 |
| 升级前的已送达旧待办没有入口 | `actions:v2:` 对仍待处理的旧格式记录补送一次可操作卡，随后去重；终态键不变，不重播已完成任务。 |

以上生产路径与相关回归已核对。样式的代码和 DOM 行为已验证，实际视觉限制见第 5 节。
