## 本轮改动及不变量

- 成果预览以 run、成果 ID、SHA 和文件名重建读组件，卸载时同步撤销活跃标记。返工对比同时绑定两侧身份，由各次请求独立对象约束结果提交。复跑覆盖同名异 ID/SHA、已读后切换、迟到成功及失败、A→B→A、旧请求结束时新请求仍在加载、左/右侧各自变化和下载。下一次返工、检查/验收请求按对应契约携带 run、节点、成果、摘要及 revision。测试使用 React 组件及 API 替身，多候选为界面夹具。生产 `rework-coordinator.ts` 仍按节点 revision 及成果归属接受返工，并按当前 attempt 固定成果 ID 和哈希接受验收。
- 任务查询先算排序、分栏和筛选所需事实再分页，在同一读事务补详细摘要及事件水位。核对分栏优先级、交付失败与未验证的优先级、归档顺序、游标过滤绑定、详情与列表同源、`tr.next_fire_at AS next_trigger_at` 及触发过滤。Q-27 用生产查询，独立重测 1 万任务首屏 50 条 p95 为 66.926 ms，门槛为 100 ms。同一次命令通过选中的 1 项，另外 3 项按过滤跳过。脚本附带的辅助 EXPLAIN 仍打印历史 SQL，未用它证明新查询计划。
- `runIdempotentCommand` 与维护扫描共用在途状态集合，重放判哈希、完成回执与超时扫描均按各自事务边界执行。记忆宿主仅识别协议 1 的特定冲突响应，其余插件错误仍沿现有失败及恢复分支处理。对账前检查 attempt、epoch、链及批准绑定，批准路径不能由面板跳过。
- 状态机与代次分别复核 `commands/nodes.ts` 迁移表校验、状态/attempt/revision CAS 和独立 Ga/Gr 条件。执行器不能自报系统终态，`run-close.ts` 按节点证据、放弃签认及未核实影响收口。真实审批和旧 attempt 的迟到状态均走各自契约。

- 坏链沿迁移、运行收口及维护扫描检查，复跑上报、执行器入口、收口和等待唤醒的隔离用例。取消、围栏与补偿仍经过状态守卫，同一 `compensation_id` 只结算一次，父子传播跳过运行中不可逆节点。HTTP 命令经请求 schema 解析，节点自由列更新白名单保持在内部迁移。
