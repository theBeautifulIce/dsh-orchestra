## 3. 状态与权限不变量

- **状态和代次。** 人工审批沿现有决定命令和 `applyTransition`，纯节点报告沿现有报告收口。新回执逻辑只读固定运行及工作流摘要，校验已完成审批节点、已生效人审决定、审批尝试、链头及签名链上的实际状态迁移。保护步骤接收到的是批准事实。错误会话、节点或报告不会因修正回合获得额外权限。
- **时限与停止。** 完成报告格式修正仅允许同一次尝试的一轮补报，工具注册约束及宿主拦截同时生效。补报不续执行时限，也不改变正在等待确认的停止凭据。旧的时钟检查点和不确定恢复入口保留，近邻回归覆盖期限、断线及恢复。
- **协作与幂等。** 信箱消息携带同运行、双方尝试、动作代次、执行会话和签名事实。迟到回复只允许对已有请求操作，发件人的正常完成须有签名报告登记。收件人仍需存活、租约有效、当前代次、围栏未触发。截止时间、反向时钟、撤销和取消检查仍在。行摘要及修订比较保护更新，重发复用已有记录，信箱继续只作参考。
- **成果与隔离。** 阻塞中的局部正文只从已完成步骤、当前尝试和确认计划取出，再核对内容摘要。来源通知保留原任务、运行和会话权限校验。部分可交付不能授权外部操作，不能放过审批或把局部成果宣布为整项成功。
- **授权引用。** 审批名与缺口处理必须能追到用户同一来源原句。最终增量补查原句局部否定，避免只截取「报告缺失」而去掉「不要」。规划入参在真正执行前隐藏常见单行、无标签、多行和表格的数字操作数，并保留操作说明。计划和运行仍保留原始数据；批准后的执行使用原有精确绑定。
- **最后增量。** 回合结束后在常显尾部复用原有审批入口。点击仍实时核对来源会话、任务、运行和决定的归属。终态摘要从经所有者校验的信箱记录显示谁已回复，回信内容没有进入成果验收。已核对缺口报告授权的任务，仅对标有规划风险、未指定模型、无工具且初始档位无法分配的步骤加入一次复核。复核只可更新原有节点的复杂度和依据，沿统一规划时限及取消信号。即时异常保留原计划，既有按档位分配和派发授权继续生效。 [审批通知](../../src/client/dsh-orchestra-notice.tsx) · [会话结果](../../src/service/chat-native.ts) · [规划复核](../../src/service/task-planning.ts)
- **既往风险。** 沿新路径复核已经收口的 `P1-2026-11-16-01` 时钟检查点和 `P1-2026-11-16-02` 断链推进问题。新逻辑使用现有迁移和链闸，未增加可自由写入的 HTTP 字段或对外副作用入口。
